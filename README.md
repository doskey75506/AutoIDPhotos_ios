# AutoID Photo · iOS 证件照拼版

原生 SwiftUI 应用，使用 Apple Vision 在本机检测人脸，并使用 MODNet / Vision 人像分割处理背景，按毫米尺寸裁切并生成多张证件照的打印拼版。应用运行时无需服务器、Python 环境或网络访问；MODNet 模型转换步骤单独需要 Python。

## 使用

应用内界面首次启动按 iOS 首选语言选择：中文系统（含繁体中文）默认简体中文，其他语言默认 English。点击右上角地球按钮（English 界面显示“中文”，中文界面显示“English”）即可即时切换，选择会保存在本机。切换语言不清空照片、不重置规格，已有照片的提示与背景选项也会更新。系统相册、分享面板等系统界面及权限弹窗由 iOS 的语言设置决定。

1. 打开 App 直接进入拍摄页，默认使用前置摄像头。文件夹选择相册照片，快门拍摄，相机图标重拍；实时预览时可切换前后摄像头。首次使用需允许相机权限。
2. 拍摄或导入后显示人脸方框；首次载入的初始方框（包括模拟器手动回退框）按原框高度向上扩展 20%、向下扩展 10%，到原图边缘即截断，左右范围不变。框旁显示“人脸范围，可拖动调节”。拖动内部移动、拖动四角缩放，后续编辑不会再自动扩展。
3. 点击底部“生成照片”，弹出简要说明、证件类型下拉菜单、打印及背景设置。预设模式隐藏数值编辑；选择“手工设定”才显示照片尺寸、头高及可选头顶留白。填写名称并点“保存手工参数”可保存全部照片和打印参数，同名保存更新，之后可从菜单再次选择。
4. 点底部醒目的“确定并生成”开始处理。确认页按新规格检查当前方框；取景不足时可点“应用规格并调整人脸范围”，返回调整后再生成。取消不应用草稿；主动保存的手工参数仍保留。
5. 检查单张与整版预览，两种照片各有一个分享菜单。菜单提供保存到照片和分享 JPEG，打印版另有 PDF。按设定纸张尺寸、100% 实际大小打印，并用尺核对成品。

首次选择“保存到照片”时请求照片读写权限，系统可提供有限访问和完全访问选择。分享菜单中的“照片访问权限”可申请权限或检查当前授权；已选有限访问时，显示“打开设置”以切换完全访问。有限访问仍可保存，未获授权或受系统限制时同样提供说明与设置入口。无需照片权限也可使用系统选择器导入或分享为文件。

新安装的初始几何参数沿用 Python 项目的 `Config/photo.cfg`，对应英国护照参考值；已有照片、语言及规格偏好继续保留：

| 项目 | 默认值 |
| --- | --- |
| 单张宽 × 高 | 35 × 45 mm |
| 头顶至下巴 | 29–34 mm，目标取中值 31.5 mm |
| 打印纸宽 × 高 | 6 × 4 英寸（152.4 × 101.6 mm） |
| 分辨率 | 默认保留原图裁切像素；关闭后按指定 DPI 输出（初始 300 DPI） |
| 间距 / 背景 | 2 mm / 纯白 |
| 背景清理方式 | 人像模型（优先 MODNet，未包含模型时使用 Vision） |
| 排版 | 4 列 × 2 行，共 8 张 |

“保留原图分辨率”默认开启，已有设置缺少该字段时也自动开启，并保留其余参数。相机按当前格式支持的最大照片尺寸请求高质量拍摄；实际尺寸由设备返回。相册与相机输入不再限制长边为 3000 像素，按完整像素纠正方向。单张证件照保留头部占幅所决定的裁切区域像素，不为满足固定 DPI 而缩小或放大；JPEG 按实际像素写入横纵 DPI，保持设定的物理尺寸。PDF 直接使用该单张照片排版。打印 JPEG 按原图有效 DPI 生成，但上限为 2000 万像素，达到限制会提示使用 PDF；此限制不降低单张精度。关闭该选项可恢复 150–600 DPI 的固定输出，300 DPI 时默认单张为 413 × 531 px、整版为 1800 × 1200 px。预览下方显示两种 JPEG 的实际像素尺寸。

简要使用说明移到生成前确认页，共三步，每步一句，英文每句（包括编号）不超过 10 个词；启动不再显示设置页。新安装及恢复默认时背景为白色，其他默认值不变。切换证件规格保留当前背景、打印纸、DPI 和分辨率模式；已有保存的背景偏好继续保留。确认页提供“恢复默认值”，恢复设置草稿后仍需确认生效，不删除照片、语言偏好或已命名的手工参数。预设含可选头顶留白，旧设置没有此字段时仍按原有方式垂直居中。

实时预览使用当前摄像头的 `AVCaptureDevice.RotationCoordinator` 获取方向，分别应用预览与拍照角度，不假设所有传感器在竖屏时都需要旋转 90°。切换前后摄像头会重新绑定协调器，前摄镜像独立处理。相机方向需在真机回归验证（模拟器没有摄像头）：

- 竖屏冷启动，确认前摄人物直立、镜像正常；拍摄后确认原图直立。
- 切换后摄，再切回前摄，每次检查预览和拍摄结果。
- 横屏后转回竖屏，检查预览方向，并在两种方向各拍一张。
- 重拍、从规格页返回和后台恢复后，重复检查；同时覆盖新款与旧款 iPhone、iPad。

原始背景要求完整裁切区域都在原图内；纯白、浅灰、蓝色、红色背景允许裁切超出原图上边缘，并以相同背景色补齐，但左右或底部缺失仍会报错。选定的头部左右边缘必须完整保留，不会缩小脸部来改变占幅。“生成照片”按钮固定在拍摄页底部，有照片后即可打开确认页切换规格；取景不合格时禁用确认页的“确定并生成”。拼版保持单张物理尺寸，以设置的最小间距（至少 0.5 mm）计算行列数，再将剩余空间均匀分配到行列间距及四周留白。“背景”栏仅保留“照片背景”设置项；纯白为 RGB(255,255,255)，浅灰为 RGB(240,240,240)，蓝色为 RGB(67,142,219) / #438EDB，红色为 RGB(255,0,0) / #FF0000（蓝、红参考 [证件照大师换底色工具](https://id-photo.cn/color/) 的纯色色块），同时用于背景替换和原图上方补白。与 Python 版一致，照片之间及外侧余白使用独立的中灰色（127/255），与白色或浅灰照片背景区分，方便识别每张照片的裁切边界；间距足够时添加照片外部裁切标记。预览、JPEG 和 PDF 使用同一配色。不再支持零间距；旧设置及已保存手工参数中低于 0.5 mm 的值在载入时自动提升至 0.5 mm。间距参数继续保存在配置中，但确认页不再显示其输入行及 0.5 mm 说明；实际均匀间距可能更大。

打印排版由确认时所选证件的毫米尺寸、纸张英寸尺寸和间距共同计算，单张裁切、JPEG、PDF 使用同一份确认参数，不读取旧规格凑固定张数。结果显示实际采用的单张毫米及纸张尺寸；两种打印导出共用物理位置换算。精确整除时仅容忍浮点舍入误差，不缩小照片。美国护照/签证单张 50.8 × 50.8 mm：6 × 4 英寸纸在至少 0.5 mm 间距下为 2 列 × 1 行共 2 张，水平方向间隔和两边留白各约 16.93 mm，垂直居中；不能以缩小照片或零间距强排 6 张。默认 35 × 45 mm 的 8 张拼版，横向间距及两边留白为 2.48 mm，纵向间距及上下留白约 3.87 mm。若版面较紧，优先保证照片间最小距离、保留最大可排张数，仅减少对称外侧留白；只有一张的方向居中放置。更换纸张或证件规格会重算，输出打印仍须使用 100% 实际大小。

确认页的证件类型、保存的手工规格及背景菜单会逐项使用当前照片、人脸框和纸张参数判断能否生成；无法使用的选项显示为灰色并禁止选择，“手工设定”保留可编辑入口。可展开“灰色选项：查看原因与重拍建议”查看每项的原因，并直接返回拍摄界面。提示区分头顶、左侧、右侧、下方空间不足及头部两侧会被裁切；纸张放不下照片时提示调整纸张。与实际生成共用裁切检查，纯色背景允许补齐顶部，不会被错误禁用。此检查不预测分割模型质量或官方受理结果。

真机/模拟器交互回归：冷启动直接显示拍摄页；载入照片检查初始扩展与标注；拖动后点击生成才出现设置；切换预设不显示数值；选手工设定并保存命名参数、重启后复用；取消不改变当前配置；无效框无法确认生成但可应用规格后返回调整；有效框点确认后只生成一次并显示两种导出。再检查白色默认背景、恢复默认不清空手工库、间距行已隐藏、不可用菜单项置灰、展开针对性建议及重拍入口。中英文及 iPhone/iPad 各检查一次。

## 构建与安装到 iPhone

要求 macOS、Xcode 16 或以上、iOS 17.6 或以上（当前 target 设置）。工程无外部依赖。

1. 打开 `AutoIDPhoto.xcodeproj`。
2. 在 Xcode → Settings → Accounts 登录 Apple ID。
3. 选择 AutoIDPhoto target → Signing & Capabilities，选择自己的 Team，启用 Automatically manage signing；如 Bundle Identifier 被占用，改为自己的唯一标识。
4. 用 USB 连接并信任 iPhone，按 Xcode 提示在手机启用开发者模式。
5. 在运行目标选择该 iPhone，按 ⌘R 安装运行。首次运行根据需要允许相机、照片权限。相册选择使用系统选择器，不需要读取整个相册。

个人开发签名有效期和设备限制由 Apple 账户类型决定；过期后可通过 Xcode 重新安装。本仓库不包含签名证书或已签名 IPA。

命令行检查（不签名，不可直接安装）：

```sh
xcodebuild -project AutoIDPhoto.xcodeproj -scheme AutoIDPhoto \
  -configuration Debug -sdk iphoneos \
  -derivedDataPath /private/tmp/autoid-derived CODE_SIGNING_ALLOWED=NO build
./scripts/test.sh
```

几何测试通过 Swift 编译器在 macOS 上运行，不依赖模拟器，覆盖默认及自定义纸张排版、头高换算、裁切边界、配置持久化、非法输入、至少 0.5 mm 的均匀排版/紧密排版/零间距迁移，以及前景保留、蒙版方向/行间距、软边混合、空蒙版拒绝、旧设置迁移、证件预设头高与留白、手工参数保存/同名更新/损坏数据、初次检测扩展，以及方框平移、四角缩放、越界限制、编辑后打印尺寸及 JPEG 像素尺寸/DPI 元数据。

## 模拟器试运行

在 macOS 普通终端进入本目录执行：

```sh
./scripts/run-simulator.sh
```

脚本优先使用已启动的 iPhone 模拟器，否则启动一个已安装的 iPhone 模拟器，再构建、安装并启动应用。没有可用模拟器时，先在 Xcode 安装 iOS Simulator runtime 并创建模拟器。可将测试照片拖入模拟器添加到相册，再通过应用选择照片。模拟器没有真实相机，预览区会提示使用文件夹图标导入照片；拍摄、前后摄像头切换和实时视频须在手机验证。

### 使用 Python 同源 MODNet

已提供 Core ML 接入代码及转换脚本；当前本地目录已生成 `AutoIDPhoto/MODNet.mlmodel` 并加入工程。重新构建后，背景处理固定使用人像模型，通过 Core ML 推理，背景处理不再调用 Vision。若其他检出目录缺少该文件，请先执行下面的转换步骤，否则模型方式使用 Apple Vision。人脸定位仍使用 Vision。

在有网络访问的 Mac 普通终端运行一次：

```sh
cd /Users/jialishen/Coding/IOS/AutoIDPhoto
./scripts/prepare-modnet.sh
```

脚本在本目录创建隔离的 `.model-tools` Python 3.11 环境，不更改原 Python 项目。安装约定版本的 PyTorch、torchvision、NumPy 和 coremltools，读取原项目的 `modnet_webcam_portrait_matting.ckpt`，生成 `AutoIDPhoto/MODNet.mlmodel`，成功后自动加入 Xcode target。随后停止应用、按 ⌘R 重新构建，并用非原始背景验证人像分割。可通过 `--checkpoint photographic` 使用已有 photographic 权重；默认 webcam 与原 `segmentor.py` 一致。

可运行 `./scripts/prepare-modnet.sh --verify` 额外比较转换后模型与 PyTorch 的 alpha 输出（需要本机 Core ML 推理服务正常）。转换脚本默认还会验证 TorchScript 与原 PyTorch 网络的输出一致；这个检查不能替代 Core ML 数值对比及真机验收。

模型使用 RGB 输入、`像素 / 127.5 - 1` 归一化、单通道 alpha 输出。当前转换固定为 512 × 512：原图缩放至正方形推理，蒙版映射回原图后合成；与原 Python 按比例、32 的倍数缩放的流程存在差异，极端长宽比的边缘效果须单独核对。模拟器使用 CPU，手机允许系统选择计算设备。模型随应用离线运行，不上传照片。

转换需要读取本机 Python 项目的 MODNet 源码与权重。原项目携带的旧版 README 声明 CC BY-NC-SA 4.0；分发模型时请同时核实所用权重的授权及来源。源码参考 [MODNet](https://github.com/ZHKKKe/MODNet)，转换方式参考 [Apple Core ML Tools](https://apple.github.io/coremltools/docs-guides/source/image-inputs.html)。

本环境已验证权重加载及 TorchScript 一致性，本地后续已生成 Core ML 文件。尚未在当前执行环境完成 Core ML 推理数值对比及真机验收；文件存在和接入代码通过检查不等于 MODNet 推理已验证。

### 模拟器推理错误

模拟器构建会为 Vision 请求的各计算阶段选择其支持的 CPU，以规避不可用的加速设备。背景合成使用 Core Graphics 解码后的 sRGB 像素与 8 位人物蒙版直接混合，不依赖 Core Image / Metal 蒙版渲染。若仍出现 `Could not create inference context` 等底层推理错误，人脸检测步骤会保留原图、明确提示改用手动定位；未检出人脸或检出多人仍正常报错。若背景分割失败，不会把未处理图片当作已抠图结果；可主动在规格中选择“原始背景”继续验证排版。手机构建仍使用系统自动选择的计算设备，分割效果须用真机确认。输出前会检查蒙版格式、前景像素和头部区域置信度；若人物蒙版为空或未覆盖头部，会停止生成并提示，而不会输出纯色拼版。

## 打印与照片要求

优先使用 PDF：页面大小以物理单位写入，单张位置与宽高按毫米换算。JPEG 也写入 DPI。选择与设置一致的纸张，使用 **100% / 实际大小**，关闭适应页面、填满和无边距自动放大；打印服务可能忽略 DPI 或增加放大，必须用尺核对成品 35 × 45 mm。检查发丝、肩部边缘和背景是否干净。

本工具提供证件照裁切、背景处理与打印排版功能。请人工检查人物边缘、背景和成品尺寸；需要保留照片背景时，可选择“原始背景”。

应用会将人物蒙版与所选背景的合成结果用于输出。MODNet 的 iOS 输入尺寸及预处理与 Python 原始流程存在差异，边缘效果须通过实际照片核对。
